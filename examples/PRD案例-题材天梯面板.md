## 1. 需求概述

- **背景**：目前复盘中，没有任何一个面板能体现题材的轮动规律和主升规律，单纯看题材强弱，很难知道这个题材是高位题材还是低位题材。
- **目标**：新增一个面板，能展示题材的轮动关系和高位低位关系。
- **范围**：Web 端复盘首页 + 运营后台（每日题材数据页，逐题材录入等级）。盯盘页与移动端不涉及。
  > 本行原写「录入等级**与升降级**」，已按 7.2-16 收窄：升降级不支持人工录入，一律由算法算。

- **现状基线**（agent 核实，2026-09-07）

  | 项 | 现状 | 对本需求意味着什么 |
  |:--- |:--- |:--- |
  | 多空循环横条 | 已完整实现：运营每日录入，已有面板在用，连续同值合并成段 | 直接复用，零新增 |
  | 题材当日涨跌幅 | 🔴 仓库里有**两个**都叫「涨跌幅」的数：一个是流通市值加权，另一个遇停牌复牌会虚高十几个百分点（读代码 + 线上抽查） | 必须用加权那个，口径写死在定案里 |
  | 题材强弱自动算法 | 已上线，有可配阈值、可全量重算、人工值优先 | 天梯算法参考它的「形状」，但不能直接复用（见 3.1.2） |
  | 每日题材建档 | 每个交易日收盘后自动继承上一日的题材列表；线上约 80 个交易日、每日二十多个题材 | 够默认区间 |
  | 题材在档的连续性 | 🔴 约 80 个交易日里，只有个位数的题材全程在档，其余都断断续续（线上数据） | 「等级累积」最大的坑，见 3.1.3 |

  | 命名 | 已有「连板天梯」「实时连板天梯」两个面板 | 新面板名要避免混淆，见 7.2-20 |

## 3. 功能需求

### 3.1 复盘-新增题材天梯面板

> 下面【】各项是**人写的原文**，只把一个具体个股名换成了「某个股」，字符画重排了对齐，其余照录（含标点与笔误）；agent 的补充从 3.1.1 起。

【面板名称】题材天梯

【面板布局】
1. 底部横轴显示日期
2. 纵轴为题材等级
3. 1级为最低，依次向上2，3，4，5，6级等
4. 顶部显示多空循环，取admin后台的大盘节奏数据

【内容】
1. 显示升级、降级、平级，也可以不展示
2. 显示题材名称和题材涨跌幅

【UI交互】
1. 鼠标点击和悬浮题材上面，显示浮窗
2. 浮窗内容：题材名称、涨跌幅、最高连板：某个股 3板、5连板2个、3连板1个、2连板1个、首板2个、涨停数、跌停数、龙头、补涨、情绪、等有标签的股票
3. 面板可以左右滑动，显示更多内容，默认展示90天内容
4. 目前等级高度不做限制，你可以程序层面限制到20级

```
|-------------------------------------------------------|
|   多方循环      |    空方循环       |    多方循环        |
|                |                  | 平 3级大金融 +3.21% |
|                | 降 2级大消费 +4.21%|                    |
|                | 升 2级农业   +3.21%|                    |
| 1级 CPO +3.65% |                  |                    |
| 1级 PCB +4.53% |                  |                    |
|-------------------------------------------------------|
|      9/1       |       9/2        |        9/3         |
|-------------------------------------------------------|
```

【数据来源】
1. 新增后台配置，加在每日题材数据中，支持配置等级数字和升降级数字
2. 同时新增一套算法，大概主干是，如果题材当日上涨超3%，则升级、-3%~3%平级，-3%降级。这个算法可以参考之前的弱转强标记，你可以给建议更细致些。

【面板类型】快照面板

【兼容全局组件】
1. 分享截图功能
2. VIP数据展示机制，跟随全局，所有面板一致
3. 单例面板

#### 3.1.1 🔴 核心风险：等级是「累积状态」

原文的算法只说了「今天涨超 3% 升一级」，但没说**从几级升**。今天的等级 = 昨天的等级 ± 1，所以等级是一条随时间累积的轨迹，而产品里所有已有面板都是「当天算当天」，没有同类先例。由此带出原文没写、但必须拍板的问题：

- 等级的取值范围？最低是 0 还是 1？0 级是什么意思？（→ 7.2-1）
- 算法能不能把题材一路降到出局？（→ 7.2-15）
- 人能改什么：只改等级，还是升降级也能改？（→ 7.2-4、7.2-16）
- 人工改了某一天的等级，之后的日期要不要跟着重算？（→ 定案速查 8-6）

#### 3.1.2 为什么不直接用「N 日涨跌幅分位」

agent 曾提出一个替代方案：按 N 日累计涨跌幅的分位数直接算「位置」，不需要累积状态。人否决了，理由是 N 没法取，而且反映不了题材「从 1 级一路升到 5 级」的过程（→ 7.2-5）。**这条否决决定了整个算法是累积型的。**

#### 3.1.3 🔴「题材中断」是常态，不是边缘情况

现状基线显示，绝大多数题材在档都是断断续续的。所以「题材消失几天再回来，等级从哪算」不是边界情况，而是每天都会发生的主路径（→ 7.2-2）。

#### 3.1.4 空态与降级

| 情形 | 表现 |
|:--- |:--- |
| 复盘日没有建档数据 | 空态，保留面板头与滑动控件；**不回退到上一交易日** |
| 可见区间内建档天数不足 | 正常渲染已有天数，不补空列 |
| 多空循环横条某段未录 | 中性灰段（上线初期只有少数几天有值，横条大部分会是灰的） |
| 某题材某日不在档 | 该列没有它的格子，不画连线、不留占位 |
| 浮窗明细加载中 | 骨架屏，不写裸文字「加载中」 |
| 龙头未标注 | 浮窗不显示龙头行（纯人工标注，没有算法兜底） |
| 刚上线、还没人标过等级 | 面板整体为空（见 7.1-2），**这是正常的** |

## 4. 非功能需求

> 原文这一节写的是技术要求（固化方式、接口切分、跑批耗时）。按现行模板，这里只保留用户看得见的部分，技术内容归 spec 的设计。

| 项 | 本需求 |
|:--- |:--- |
| 刷新与时效 | 每个交易日盘后计算一次，次日早上有一次兜底重算；运营改等级后，该题材之后各日的等级同步更新 |
| 故障与重启 | 盘后计算失败时，由次日早上的兜底重算补上 |
| 谁能看 | 跟随全局权限 |
| 响应速度 | 左右滑动、拉宽改列数都不发请求，不等待；浮窗明细悬浮时按需加载 |

前台、后台各出一份原型，均用真实数据规模跑过、浅暗两种主题都验过。

- **7.3-29** 🟡 运营改完等级后，后台要不要提示「重算了几个交易日」？建议：不做。改完静默保存，重算在同一次请求里完成，运营感知不到差别；加载态会拖慢高频录入。

## 8. 定案速查（给落 spec 的人）

- **8-1** 面板名「题材天梯」，快照面板、单例。（出处：7.2-20、§3.1）
- **8-2** 等级 0~20；0 = 出局不显示，1~20 显示。（7.2-1）
- **8-3** 入场只能由运营人工标 ≥1 级；算法不让 0 级题材进场。（7.2-2）
- **8-4** 出局只能人工（标 0，或从每日题材数据删掉 → 断档归 0）；算法降到 1 级为止。（7.2-15）
- **8-5** 升降：当日加权涨跌幅 ≥ +3% 升、≤ −3% 降、其间平；一期只用涨跌幅。（7.2-3、§1 现状基线）
- **8-6** 人工只改等级；人工值成为新基线，其后各交易日按日期顺序重算该题材。（7.2-4、7.2-16）
- **8-7** 默认 60 个交易日，滑动不发请求；看全 60 天靠滑动不靠拉宽。（7.2-14、7.2-25）
- **8-8** 列数随宽度自适应 5~16 列。（7.2-25）
- **8-9** 纵轴只渲染有数据的等级；格子区面板级纵向滚动。（7.2-8、7.2-24）
- **8-10** 同级竖排、当日涨幅降序、同值按运营排序。（7.2-18）
- **8-11** 点击 = 广播联动 + 点亮全轨迹；悬浮 = 浮窗。（7.2-17、7.2-26）
- **8-12** ST 开关只影响浮窗家数；等级与涨跌幅不跟。（7.2-10、7.2-19）
- **8-13** 多空循环横条复用已有实现，不画未来列。（§1 现状基线、§5）
- **8-14** 上线顺序：数据层 → 算法 → 回填（全 0 正常）→ 后台录入 → 冷启动录入 → 前台面板。（§6）
