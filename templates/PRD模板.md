## 4. 非功能需求

> 只写**用户看得见、能验收**的行为。技术方案（技术栈、表、接口、缓存、定时任务）一律写在 spec 的设计里，本文档不写。
> agent 讨论时发现的技术约束：影响产品取舍的，进 §7.1（告知）或 §7.3（待确认），写成「代价是用户会看到 X」；不影响的不写。
> 本文档里出现的技术数值都只是建议，以 spec 的设计为准。

| 项 | 本需求（不涉及写「不涉及」） |
|:-- |:---------------------------- |
| 刷新与时效 | 多久更新一次；数据最晚几点就绪 |
| 故障与重启 | 服务重启、上游数据缺失或延迟时，用户看到什么；哪些东西不能丢 |
| 谁能看 | 公开 / 登录 / 付费；后台入口给谁用 |
| 响应速度 | 用户能接受的等待（例：打开 1 秒内出内容） |
