# 第 4 章 · 从需求到开发的定档

> 本章待写。计划内容：

- 判类型：产品需求 / 技术改造 / 缺陷修复 / 工程任务；类型决定验证纪律（修缺陷先复现、重构先证明旧行为）
- 先只读调研，报四行：根因或目标、影响面、同类、改法
- A 直接改 / B 轻量计划 / C 完整：只问「改法能不能一句话说清」「影响面核实过没有」
- 风险加码：风险不定档，在档位上叠加要求，大风险一票生效
- 都先写需求，不先写设计；歧义靠写明假设加 review 兜住
- C 档的产品需求尽量先出 PRD 配原型，再转 spec；新模块、新页面尤其要出（第 5 章）
- spec 模板与只查结构的 lint
