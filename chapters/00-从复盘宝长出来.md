# 第 0 章 · 从复盘宝长出来

TierSpec 的每一条规则都不是先设计好的，而是在一个真实项目里被问题逼出来的。这个项目叫**复盘宝**。

🔗 **https://fupanbao.top**

## 它是什么

复盘宝是一个 A 股每日复盘与实时行情看板：涨停梯队、龙虎榜、主题板块、大盘天气、个股 K 线与分时行情，帮投资者盘后系统化复盘、盘中盯实时走势。另有一条自动写作流水线，每天收盘后生成当日复盘文章。

它由一个人加 AI 从零写起、部署、运维：pnpm monorepo，包含用户端、运营后台、API 服务（Fastify + Prisma + PostgreSQL）与 Python 行情采集端，跑在云服务器上。

## 为什么这个项目逼得出一套规则

- **时间是硬约束。** 交易日、竞价、盘中、盘后，每个时点该看到的数据都不一样，一切时间按北京时间算。时间错一处，数据就错一片。
- **数据错了就是错了。** 接口 200、页面不报错，不代表数据是对的。AI 最容易「验证通过」一个错误的结果。
- **盘中不能出事故。** 部署、改数据、改采集都要避开交易时段，并且撤得回来。
- **一个人维护多端。** 没有同事帮你 review，只能让流程和机器门槛来充当第二双眼睛。

## 怎么读这本书

每条规则都带着它被逼出来的问题。照抄规则不如照着判据裁剪：先看你的项目有没有同样的问题，再决定要不要这条规则。

复盘宝的源码不开源，本仓库只讲方法。
